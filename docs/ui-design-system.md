# UI-документ: дизайн-система сайта «Свой Доктор»

Дата: 2026-07-18. Продолжение `ux-strategy.md` — здесь фиксируются визуальные решения: токены, компоненты, раскладки страниц. Реализация: SvelteKit + Tailwind + shadcn-svelte, SSR (Squidex как CMS, чтобы сотрудники клиники могли редактировать контент/прайс без разработчика), PWA.

Процесс: этот документ фиксирует систему **до** визуального макета — следующий шаг после согласования: Artifact-мокап главной страницы по этим токенам, затем перенос в реальные Svelte-компоненты через Svelte MCP (`svelte-file-editor`, `svelte-autofixer`).

---

## 1. Принципы дизайна

Выведены из `ux-strategy.md` (раздел «Экологичность») и `content-and-brand-voice.md` — дизайн не должен противоречить тому, что уже честно установлено про бренд:

- **Тёплый, но не игрушечный.** Клиника — не мегаклиника с 24/7 и роботизированным сервисом (как ZOOVITA), а локальный кабинет с реальными людьми и рейтингом 4.9. Дизайн должен читаться как «свои», а не как корпоративная сеть.
- **Честная иерархия, а не декоративная сложность.** Цена, часы работы, кнопка связи — всегда физически заметны, не спрятаны за анимациями или лишними кликами. Это прямое следствие «экологичности» из UX-документа.
- **Настоящие фото, не стоки.** У клиники уже есть сильный визуальный актив — реальные фото пациентов и команды (`docs/media/`). AI-генерация или стоковые фото животных здесь будут хуже, а не лучше.
- **Один акцентный цвет, не десять.** У бренда уже стихийно сложился фиолетовый (лого + все промо-карточки) — фиксируем его как основной, а не изобретаем новую палитру.

## 2. Цветовая палитра

Приближено по скриншотам лого и промо-карточек (`docs/media/logo.png`, `docs/media/post-promo-sterilizatsiya-may2026.jpg`). Это **рабочие значения**, не пипетка по оригинальному файлу — при вёрстке стоит сверить с клиникой, если у них сохранился исходник лого в векторе.

| Токен | HEX (рабочее приближение) | Использование |
|---|---|---|
| `--brand-primary` | `#6E2C8C` | Основной фиолетовый — хедер, кнопки, акценты, лого |
| `--brand-primary-dark` | `#4E1F66` | Ховеры, текст на светлом фоне, глубокие тени |
| `--brand-accent` | `#B5459C` | Розово-магентовый акцент — бейджи цен/акций (как «13.000 тенге» в промо-карточках) |
| `--brand-cream` | `#FBF7F5` | Фон карточек/секций вместо чистого белого — теплее, ближе к фону лого |
| `--brand-ink` | `#1F1B24` | Основной текст — не чистый чёрный, чуть тёплый тёмный |
| `--success` (2ГИС-бейдж, «услуга доступна») | `#3E9B5C` | Нейтрально-зелёный, стандартный, не бренд-специфичный |
| `--warning` (уточняйте цену) | `#C17A1F` | Для пометок «цена уточняется по телефону» — не красный (это не ошибка, а нормальное состояние) |

Не используем чистый красный для ошибок формы без необходимости — избыточная тревожность не подходит теме «поход к врачу с больным питомцем».

## 3. Типографика

- **Заголовки**: шрифт с засечками или полу-декоративный, echo лого («Свой Доктор» на лого — с засечками) — например `Playfair Display` или `Lora` для H1/H2, создаёт ощущение «настоящей клиники», а не дженерик-стартапа
- **Текст/UI**: чистый sans — `Inter` или `Manrope` (уже вероятно доступен через shadcn-svelte defaults) для тела текста, кнопок, форм — читаемость важнее индивидуальности здесь
- **Масштаб** (Tailwind default type scale, без кастомных ступеней): H1 `text-4xl md:text-5xl`, H2 `text-2xl md:text-3xl`, body `text-base md:text-lg` — сознательно чуть крупнее дефолта, учитывая немолодую часть аудитории (см. `ux-strategy.md`, раздел «Экологичность» → доступность)

## 4. Сетка и отступы

Стандартная Tailwind-шкала отступов, без кастомной сетки. Контейнер `max-w-6xl` для десктопа, mobile-first (весь сайт проектируется от 375px вверх, а не наоборот — аудитория заходит с телефона чаще, регион не мегаполис).

## 5. Компоненты (mapping на shadcn-svelte)

| Нужда из UX-документа | Компонент shadcn-svelte | Кастомизация |
|---|---|---|
| Кнопка звонка/WhatsApp на каждом экране | `Button` (variant `default`, размер `lg`) | Плавающая версия на мобильном — fixed bottom, как у ZOOVITA/Талисмана (оба используют этот паттерн — практика подтверждена конкурентами) |
| Форма заявки на приём + подсказки по анализам | `Form` + `Select` (услуга) + `Input` + `Textarea`, `Alert` для подсказки | `Alert` появляется динамически при выборе услуги с подготовкой (см. `services-and-pricing.md`) |
| Блок акции с датой действия | `Card` + `Badge` (для цены/срока) | Не показывать пустую карточку, если акции нет — весь блок скрывается, не оставляет дыру в макете |
| Прайс лаборатории (много позиций по категориям) | `Accordion` (категория) + `Table` внутри | Сворачиваемые категории — иначе длинный прайс перегружает страницу с первого экрана |
| Рейтинг 2ГИС на главной | `Badge` + иконка звезды, ссылка на профиль 2ГИС | Не имитировать сам виджет 2ГИС — просто честная цифра со ссылкой |
| Иконки-в-кружках для УТП (уже есть как паттерн в промо-карточках клиники) | Кастомный компонент на основе `Card` без строгой shadcn-примитива | Прямое продолжение визуального языка, который клиника уже использует в Instagram-промо |
| Карточки животных «ищет дом» / доноров | `Card` с изображением | Раздел «Мы помогаем» |
| FAQ / просветительский контент | `Accordion` | Если реализуем Could-have блог/FAQ |

## 6. Специфичные для проекта паттерны

- **Плашка «уточняйте цену»** — не пустое место и не ошибка-стиль (см. `--warning` выше), а нейтральный, спокойный элемент. Появляется там, где в `services-and-pricing.md` отмечено «цена не публикуется» (приём врача, УЗИ вне акций).
- **Блок акции всегда с датой окончания.** Прямое следствие наблюдения из `services-and-pricing.md`: акции клиники плавающие, привязаны к периоду — сайт не должен создавать впечатление вечной скидки.
- **WhatsApp deep-link из формы** — визуально кнопка не должна выглядеть как «отправить на сервер» (никаких спиннеров/подтверждений о получении, которых на самом деле не происходит на MVP-этапе, см. `ux-strategy.md` 7.1) — честная подпись вида «Открыть WhatsApp с готовым сообщением».

## 7. Раскладки страниц (по IA из ux-strategy.md)

**Главная**: hero (заголовок + фото кабинета/команды + кнопка звонка) → блок текущей акции (если есть) → УТП иконками-в-кружках (своя лаборатория, доказательная медицина, рейтинг 4.9) → превью раздела «Мы помогаем» → контакты/карта в футере.

**Услуги и цены**: группировка по сценарию (лечение → профилактика → лаборатория аккордеоном), не по алфавиту — повторяет структуру раздела 5 `ux-strategy.md`.

**О клинике**: адрес, часы, текст про доказательную медицину (контент уже есть в постах), реальные фото кабинета.

**Мы помогаем**: карточки животных/доноров, ссылка на приют «Досым» — эмоциональный, фотографичный раздел, меньше текста, больше изображений.

**Контакты**: карта, 2ГИС-ссылка с рейтингом, часы, телефон/WhatsApp-кнопка — минимум лишнего, максимум скорости получения контакта.

## 8. PWA и SSR — что это меняет для UI

- **SSR (Squidex)**: контент (прайс, акции, тексты) редактируется сотрудниками клиники без разработчика — значит компоненты должны деградировать аккуратно при пустых/неполных полях (например, если сотрудник не заполнил «дата окончания акции» — блок должен скрываться, а не показывать «undefined»)
- **PWA**: иконка на главном экране телефона — нужен простой, узнаваемый фавикон/иконка на основе лого (уже есть, `docs/media/logo.png`), манифест с `--brand-primary` как цвет темы

## 9. Доступность

- Контраст: `--brand-primary` (#6E2C8C) на `--brand-cream` (#FBF7F5) — проверить по WCAG AA при вёрстке (тёмный фиолетовый на светлом фоне обычно проходит, но нужно подтвердить инструментом, не на глаз)
- Размер тач-таргетов кнопок — не меньше 44×44px, учитывая, что часть аудитории может быть менее уверенной в мобильном интерфейсе
- Не полагаться только на цвет для статуса цены (фиксированная/уточняйте) — дублировать текстом, не только цветом бейджа
