# UI-документ: дизайн-система сайта «Свой Доктор»

Дата: 2026-07-18. Продолжение `ux-strategy.md` — здесь фиксируются визуальные решения: токены, компоненты, раскладки страниц. Реализация: SvelteKit + Tailwind + shadcn-svelte, SSR (Squidex как CMS, чтобы сотрудники клиники могли редактировать контент/прайс без разработчика), PWA.

Процесс: этот документ фиксирует систему **до** визуального макета — следующий шаг после согласования: Artifact-мокап главной страницы по этим токенам, затем перенос в реальные Svelte-компоненты через Svelte MCP (`svelte-file-editor`, `svelte-autofixer`).

---

## 1. Принципы дизайна

Выведены из `ux-strategy.md` (раздел «Экологичность») и `content-and-brand-voice.md` — дизайн не должен противоречить тому, что уже честно установлено про бренд:

- **Тёплый, но не игрушечный.** Клиника — не мегаклиника с 24/7 и роботизированным сервисом (как ZOOVITA), а локальный кабинет с реальными людьми и рейтингом 4.9. Дизайн должен читаться как «свои», а не как корпоративная сеть.
- **Честная иерархия, а не декоративная сложность.** Цена, часы работы, кнопка связи — всегда физически заметны, не спрятаны за анимациями или лишними кликами. Это прямое следствие «экологичности» из UX-документа.
- **Настоящие фото, не стоки.** У клиники уже есть сильный визуальный актив — реальные фото пациентов и команды (`docs/media/`). AI-генерация или стоковые фото животных здесь будут хуже, а не лучше. Исключение — авторские иллюстрации-маскоты в разделе «Услуги» (см. 6.1): это осознанный декоративный слой поверх настоящих фото, не замена им.
- **Один акцентный цвет, не десять.** У бренда уже стихийно сложился фиолетовый (лого + все промо-карточки) — фиксируем его как основной, а не изобретаем новую палитру. Плиточная раскладка (см. 6.1) создаёт визуальное разнообразие оттенками одного фиолетового + акцентом, не новыми цветами.

## 2. Цветовая палитра

Приближено по скриншотам лого и промо-карточек (`docs/media/logo.png`, `docs/media/post-promo-sterilizatsiya-may2026.jpg`). Это **рабочие значения**, не пипетка по оригинальному файлу — при вёрстке стоит сверить с клиникой, если у них сохранился исходник лого в векторе.

| Токен | HEX (рабочее приближение) | Использование |
|---|---|---|
| `--brand-primary` | `#6E2C8C` | Основной фиолетовый — хедер, кнопки, акценты, лого |
| `--brand-primary-dark` | `#4E1F66` | Ховеры, текст на светлом фоне, глубокие тени |
| `--brand-accent` | `#B5459C` | Розово-магентовый акцент — бейджи цен/акций (как «13.000 тенге» в промо-карточках) |
| `--brand-cream` | `#FBF7F5` | Фон карточек/секций вместо чистого белого — теплее, ближе к фону лого |
| `--brand-ink` | `#1F1B24` | Основной текст — не чистый чёрный, чуть тёплый тёмный |
| `--success` (2ГИС-бейдж, «услуга доступна») | `#3E9B5C` | Нейтрально-зелёный, стандартный, не бренд-специфичный |
| `--warning` (уточняйте цену) | `#C17A1F` | Для пометок «цена уточняется по телефону» — не красный (это не ошибка, а нормальное состояние) |

Не используем чистый красный для ошибок формы без необходимости — избыточная тревожность не подходит теме «поход к врачу с больным питомцем».

## 3. Типографика

Решение пересмотрено 2026-07-22 в Penpot (файл `svoydoctor`, страница `UI_KIT` → доска `Typography`) — заменяет более ранний вариант с `Playfair Display`/`Lora` + `Inter`/`Manrope`.

- **Заголовки**: `LXGW Marker Gothic` — рукописный маркерный шрифт с полной поддержкой кириллицы ([Google Fonts](https://fonts.google.com/specimen/LXGW+Marker+Gothic)), для H1–H4. Даёт «свой», нетиповой почерк вместо дженерик-гротеска — продолжает принцип «тёплый, но не игрушечный» за счёт контраста с нейтральным телом текста (см. ниже), а не за счёт декоративности самого текста
- **Текст/UI**: `PT Sans` для body/UI/форм — кириллический шрифт (ParaType, изначально спроектирован под русский язык), тёплый гуманистический гротеск, контрастирует с рукописными заголовками и не спорит с ними за внимание. Сознательно не `Inter`/`Manrope`, чтобы пара не читалась как дженерик-стартап на фоне декоративных заголовков
  - `LXGW WenKai Mono TC` (моноширинный) был опробован для тела текста, но отклонён — снижает читаемость на длинных абзацах (прайс, описания услуг), что противоречит доступности для немолодой части аудитории (см. `ux-strategy.md`, «Экологичность»)
- **Масштаб** (Tailwind-подобный, зафиксирован образцами в Penpot): H1 48px / H2 30px / H3 24px / H4 20px — все `LXGW Marker Gothic`; Body 16px / Lead 18px / Small 14px — все `PT Sans`. Сознательно чуть крупнее Tailwind-дефолта, учитывая немолодую часть аудитории

## 4. Сетка и отступы

Стандартная Tailwind-шкала отступов, без кастомной сетки. Контейнер `max-w-6xl` для десктопа, mobile-first (весь сайт проектируется от 375px вверх, а не наоборот — аудитория заходит с телефона чаще, регион не мегаполис).

## 5. Компоненты (mapping на shadcn-svelte)

| Нужда из UX-документа | Компонент shadcn-svelte | Кастомизация |
|---|---|---|
| Кнопка звонка/WhatsApp на каждом экране | `Button` (variant `default`, размер `lg`) | Плавающая версия на мобильном — fixed bottom, как у ZOOVITA/Талисмана (оба используют этот паттерн — практика подтверждена конкурентами) |
| **Форма записи на приём** (см. `ux-strategy.md` 4.1, флоу A/B) | `Sheet` (боковая панель, не центрированный `Dialog` — уточнено 2026-07-24) + `Form` внутри: `Select` (обязательно — выбор услуги из прайса), `Input` (имя, телефон), `Textarea` (повод), `Alert` для подсказки по подготовке | Открывается из хедера/hero/карточки услуги/карточки признака, выезжает сбоку, не уводит со страницы. Под полем телефона — короткая подпись со ссылкой на `/privacy`: телефон — персональные данные, значит нужно честно показать, куда ведёт согласие, а не прятать это в футере. На `/apply` та же форма рендерится инлайн без `Sheet`-обёртки (см. `sitemap.md`) |
| Подсказки по подготовке к анализам внутри модалки | `Alert` (variant нейтральный/`--warning`, не error-red) | Появляется динамически при выборе в `Select` услуги с подготовкой — конкретный текст по услуге см. `services-and-pricing.md` («Подготовка к сдаче анализов»): кровь — голод 6–8ч, моча — стерильный контейнер и не более 2ч с момента сбора, соскобы — не обрабатывать участок 4–5 дней |
| Блок акции с датой действия | `Card` + `Badge` (для цены/срока) | Не показывать пустую карточку, если акции нет — весь блок скрывается, не оставляет дыру в макете |
| Прайс лаборатории (много позиций по категориям) | `Accordion` (категория) + `Table` внутри | Сворачиваемые категории — иначе длинный прайс перегружает страницу с первого экрана |
| Рейтинг 2ГИС на главной | `Badge` + иконка звезды, ссылка на профиль 2ГИС | Не имитировать сам виджет 2ГИС — просто честная цифра со ссылкой |
| Иконки-в-кружках для УТП (уже есть как паттерн в промо-карточках клиники) | Кастомный компонент на основе `Card` без строгой shadcn-примитива | Прямое продолжение визуального языка, который клиника уже использует в Instagram-промо |
| **Карточка признака** («Признаки, что пора к ветеринару», см. `ux-strategy.md` 6.1) | Тот же кастомный компонент на `Card`, что и УТП-иконки (переиспользуем форму, не изобретаем новую) | Иконка + короткая формулировка (1 признак = 1 карточка), клик открывает модалку записи с предзаполненной услугой «Приём врача». Карточки из подтверждённого контента клиники и из общеветеринарного списка визуально не различаются (не создаём ложное впечатление, что часть менее важна — обе группы ведут к одному честному действию «запишитесь») |
| **Карта в блоке контактов** (главная + `/contacts`) | Обёртка `Card` вокруг `iframe` 2ГИС-карты | Настоящий встроенный виджет карты с меткой адреса, не картинка-заглушка — рядом бейдж рейтинга 4.9 и кнопка «Построить маршрут» на 2ГИС |
| Карточки животных «ищет дом» / доноров | `Card` с изображением | Раздел «Мы помогаем» |
| FAQ / просветительский контент | `Accordion` | Если реализуем Could-have блог/FAQ |

## 6. Специфичные для проекта паттерны

- **Плашка «уточняйте цену»** — не пустое место и не ошибка-стиль (см. `--warning` выше), а нейтральный, спокойный элемент. Появляется там, где в `services-and-pricing.md` отмечено «цена не публикуется» (приём врача, УЗИ вне акций).
- **Блок акции всегда с датой окончания.** Прямое следствие наблюдения из `services-and-pricing.md`: акции клиники плавающие, привязаны к периоду — сайт не должен создавать впечатление вечной скидки.
- **WhatsApp deep-link из формы** — визуально кнопка не должна выглядеть как «отправить на сервер» (никаких спиннеров/подтверждений о получении, которых на самом деле не происходит на MVP-этапе, см. `ux-strategy.md` 7.1) — честная подпись вида «Открыть WhatsApp с готовым сообщением».
- **Запись — всегда модалка, не переход страницы** (уточнение 2026-07-21, см. `ux-strategy.md` 4.1). Единственное исключение — сама страница `/apply`, где форма и так на своей странице, поэтому `Dialog`-обёртка не нужна.
- **«Признаки, что пора к ветеринару» — без нагнетания.** Тон — как в исходном посте клиники про пироплазмоз: спокойное перечисление + прямое приглашение на приём, без красного цвета/иконок «опасности», без таймеров. Соответствует принципу «без манипулятивной срочности» из `ux-strategy.md` раздел 3.

### 6.1 Визуальное направление: плитка (Windows 8 / Metro) + стекло

Решение зафиксировано 2026-07-24 в Penpot (файл `svoydoctor`, страница «Главная») по итогам ревью первого wireframe-прохода — пользователь отметил слишком много пустого пространства в узких колоночных блоках и предложил ориентироваться на плиточный дизайн Windows 8 с современным стеклянным слоем поверх.

- **Плитки, а не карточки с воздухом.** Контент главной собирается в grid-раскладки (`Board.addGridLayout()`), где плитки стыкуются встык с минимальным гэпом (8px), а не разложены в карточки с большими внутренними отступами и большими промежутками между собой. Крупные и мелкие плитки соседствуют в одном гриде через `columnSpan`/`rowSpan` (пример: hero — большая плитка заголовка 4×4 рядом с четырьмя плитками 2×2 — фото, акция, WhatsApp, Instagram).
- **Углы: острые почти везде, круг — только для «аватарных» элементов.** Уточнено 2026-07-24 после ревью первого цветного прохода: изначальный вариант «мелкое скругление 8–12px на всех кнопках» пользователь отменил — кнопки, CTA-пилюли, переключатель РУ/КК, иконка-бейдж Telegram, гамбургер-меню — все острые (`borderRadius: 0`), как и крупные контентные плитки. Круглыми остаются только два типа элементов: лого (кружок) и плавающие кнопки соцсетей (`fixed`, поверх контента) — они держат форму «аватара/значка», а не «плитки» или «кнопки-пилюли». Внутри плиточного грида hero сами тайлы WhatsApp/Instagram (2×2, часть сетки) — острые, как все тайлы.
  **Обновлено 2026-08-13** (по прямому запросу пользователя со скриншотами-референсами): вместо двух фиксированных floating-дубликатов (WhatsApp/Instagram), выезжающих по скроллу, — один пульсирующий круглый FAB в правом нижнем углу (`src/components/social-widget`), по клику раскрывающий вертикальный список ВСЕХ соцсетей/мессенджеров из Directus (`social_links` — не захардкожено, редактор добавляет платформы сам: иконка из Iconify или своя картинка, цвет кружка, ссылка). Триггер в свёрнутом виде показывает первый элемент списка; раскрытие — не по скроллу, а по клику/тапу. Список площадок больше не ограничен WhatsApp+Instagram.
- **Стеклянный слой — не буквальный blur на тексте.** Penpot API поддерживает только `layer-blur` (блюрит содержимое самой фигуры), а не backdrop-blur — применять его к плитке с текстом испортит читаемость. Вместо этого «стекло» имитируется полупрозрачной заливкой + тонкой светлой обводкой (`stroke: #FFFFFF @ 0.18–0.25 opacity, 1px, inner`) + мягкой тенью (`drop-shadow, blur 14–16px, opacity 0.10–0.12`). При переносе в код это соответствует `backdrop-filter: blur()` + `background: rgba()` + `border: 1px solid rgba(255,255,255,.2)` — здесь уже можно использовать настоящий backdrop-blur.
- **Масштаб — «десять футов», не десктопный.** Крупные заголовки (H1 плитки hero — 84px на десктопе после ревизии 2026-07-29, было 112px после ревизии шрифтов 2026-07-24, до этого 56px), крупные CTA (высота 56–64px, шрифт 34–40px), крупные тач-зоны иконок (56–72px) — элементы должны читаться на расстоянии, не только с close-up. Это относится ко всей главной, не только к hero. Все текстовые размеры документа (раздел 3) остаются базовой шкалой для десктоп-контента вне плиточных секций (тело статей, формы) — масштаб плиточных шрифтов применён только к плиточным блокам главной, не переопределяет H1–H4/Body/Lead/Small глобально.
- **Плиточная шкала — fluid (`clamp()`), не фиксированные брейкпоинты.** 2026-07-29: значения из Penpot (112/80/64/44) в браузере читались крупнее задуманного — верхнюю границу урезали ~на 25% (112→84, 80→60, 64→48, 44→32) и сделали плавную интерполяцию по ширине вьюпорта от 375px до 1440px (`--container-content`) через CSS `clamp()` в `src/routes/layout.css` (`--font-tile-display/h1/h2/h3`), вместо жёсткого скачка на брейкпоинте `lg`. Токены ≤24px (`--font-tile-body-lg`, `--font-tile-small`) не тронуты — фиксированные px, как раньше.
- **Иллюстрации-маскоты в «Услугах»** — референс стиля: плоская, слегка текстурированная авторская иллюстрация животного (пример: маскот-панголин экрана входа Ubuntu 12.04 LTS, тёплый ограниченный цвет, декоративный фон с точечной текстурой). Это отдельный визуальный слой поверх настоящих фото клиники (см. принцип 1 выше), не замена им. **Важно**: сами иллюстрации нужно заказать художнику/сгенерировать отдельным инструментом — в Penpot сейчас стоит только плейсхолдер-плитка с подписью «иллюстрация» на месте, где должна быть готовая картинка.

## 7. Раскладки страниц (по IA из ux-strategy.md)

**Главная**: hero (заголовок + фото кабинета/команды + кнопка звонка) → блок текущей акции (если есть) → УТП иконками-в-кружках (своя лаборатория, доказательная медицина, рейтинг 4.9) → превью услуг → **«Признаки, что пора к ветеринару»** (сетка карточек-признаков, см. раздел 5 выше и `ux-strategy.md` 6.1) → превью раздела «Мы помогаем» → **блок контактов с картой** (адрес, часы, телефон/WhatsApp, встроенная 2ГИС-карта, бейдж рейтинга — как самостоятельный видимый раздел, не только в футере) → футер.

**Услуги и цены**: группировка по сценарию (лечение → профилактика → лаборатория аккордеоном), не по алфавиту — повторяет структуру раздела 5 `ux-strategy.md`.

**О клинике**: адрес, часы, текст про доказательную медицину (контент уже есть в постах), реальные фото кабинета.

**Мы помогаем**: карточки животных/доноров, ссылка на приют «Досым» — эмоциональный, фотографичный раздел, меньше текста, больше изображений.

**Контакты**: карта, 2ГИС-ссылка с рейтингом, часы, телефон/WhatsApp-кнопка — минимум лишнего, максимум скорости получения контакта.

## 8. PWA и SSR — что это меняет для UI

- **SSR (Squidex)**: контент (прайс, акции, тексты) редактируется сотрудниками клиники без разработчика — значит компоненты должны деградировать аккуратно при пустых/неполных полях (например, если сотрудник не заполнил «дата окончания акции» — блок должен скрываться, а не показывать «undefined»)
- **PWA**: иконка на главном экране телефона — нужен простой, узнаваемый фавикон/иконка на основе лого (уже есть, `docs/media/logo.png`), манифест с `--brand-primary` как цвет темы

## 9. Доступность

- Контраст: `--brand-primary` (#6E2C8C) на `--brand-cream` (#FBF7F5) — проверить по WCAG AA при вёрстке (тёмный фиолетовый на светлом фоне обычно проходит, но нужно подтвердить инструментом, не на глаз)
- Размер тач-таргетов кнопок — не меньше 44×44px, учитывая, что часть аудитории может быть менее уверенной в мобильном интерфейсе
- Не полагаться только на цвет для статуса цены (фиксированная/уточняйте) — дублировать текстом, не только цветом бейджа
